Tokens for developers: colors, fonts, spacing, components

All values come straight from the portal CSS (client-portal.html, :root variables). Use the CSS variable names so light/dark theme switching works (:root[data-theme=dark] overrides them).

CLIENT – 3.0

Post a job manually: 4-step form, validation, post

'Fill in the form manually'. Four steps: Hiring needs · Engagement details · Skill set & experience · Work location & availability. Each step has Cancel/Go back, Save & exit (keeps the draft in Searches) and Continue; the last step posts the job. Required fields are marked *. The 'Create with Skai' banner stays top-right on every step and carries all entered data across if the client switches.

CONSULTANT – 3.0

Experience: work experience, industries and experience summary

The same experience fields are used in onboarding (step 5, extracted from the resume) and here, so nothing is entered twice. Industry, subindustry, platforms, products and skills roll up automatically into the Experience summary: years (overlaps counted once), unique clients and projects. Employer, end client, subindustry and project are optional; responsibilities are required.

CONSULTANT – 4.0

Interview request → offer → accept → onboarding → project

Account with activity (portal opened without ?new=1). A client requests an interview, the consultant accepts a proposed slot, later receives an offer, accepts it and then completes a short onboarding before the project starts. Accepting the offer and onboarding are separate steps, and each onboarding step is saved so the consultant can leave and continue from the next step.
